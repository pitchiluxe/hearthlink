# AI providers and local performance agent

User request: AI provider settings, Ollama primary, OpenAI/ChatGPT then Claude fallback, recent free/local model discovery, and a background performance agent. User explicitly chose cloud requests only after enabling cloud fallback in Settings, and automatic image-quality adjustment within limits without changing security or files.

Use existing WinForms/.NET/DPAPI storage. No new packages, no cloud requests with real keys during development. Provider order is Ollama → OpenAI Responses API → Anthropic Messages API. The latter two use separately configured API keys/model IDs; keys remain in protected settings and masked controls, never logs/history. Cloud fallback is off by default. User-facing disclosure states that file-helper prompts and folder/path metadata may leave the PC when enabled; file contents/screenshots are not sent. Request/response size and timeouts are bounded; cancellation must stop fallback, malformed/security validation errors must not trigger it. No redirects with credentials.

Installed Ollama models are discovered locally and verified with /api/show for local capabilities/remote metadata; tag payloads alone are insufficient. Preferred local model is configurable. Settings can scan the official Ollama Library newest listing, including pagination, excluding embedding-only and cloud-only entries. Do not assert every model is license-free or fits hardware. No automated downloads; provide model/license links and an explicit download action with progress/cancel if implemented. External catalog failure must leave installed models usable.

The shared provider router powers the file helper without weakening its validated copy-plan/Run flow. Background performance uses Ollama only, numeric frame/round-trip/capture timing and quality metrics only. Never provide screenshots, input, paths or credentials to it; it has no general tools or file/network/security actions. Limit inference frequency, token/context sizes and model memory. Require sustained congestion, enforce configured minimum/maximum quality, cooldown and fresh data before applying suggestions; ignore idle/static-screen low FPS alone. Invalid model output or Ollama failure leaves the current profile unchanged. A manual quality choice pauses automatic adjustment for that session. Show last decision and local-agent state in Connection health and the session toolbar. No claim that enabling AI necessarily improves performance on every PC.

Default agent enabled for new sessions per user's request, with quality bounds Responsive through Full detail. User can disable it and edit limits in Settings. Use a small installed model for agent work; if none is suitable, report unavailable rather than download or use cloud silently. Main chat fallback can be enabled separately. Persist all preferences; old profiles remain valid. Build a locally reviewable next-version installer; publication is a separate release action.

Validation: mocked provider order, consent changes, cancellation, credentials/endpoint isolation, output bounds and rejection, model metadata and catalog fixtures; real preference storage/UI navigation; numeric-only agent prompts, idle behavior, bounded/cooldown actions and manual override. Core/Windows suites and isolated UI renders. Record live provider/hardware limits.

User steering: restore the main application to its previous fixed 1096×783 outer window size, remove resize/maximize, and keep page content scrollable. Viewer/file-manager window behavior is unchanged.
