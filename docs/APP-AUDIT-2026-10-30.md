# HearthLink app audit — October 30, 2026

Scope: source review across the desktop dashboard, pairing, identity persistence, direct/relay transport, host/viewer lifecycle, capture/input queues, file manager/transfers, local AI helper, updater, relay Worker and packaging. Automated checks ran locally. This is a broad engineering review, not a penetration test or proof of two-physical-PC operation. Website deployment and live infrastructure were not tested.

## Computer table fix (0.4.4)

The previous implementation drew the entire row in DrawItem, an event Windows also sends independently during hover. Painting now happens per cell in DrawSubItem: background, stripe, selection border and text share the same cell bounds. The first column is constrained to its actual width, text respects the paint clip, and ampersands display literally. Double buffering remains enabled.

Microsoft documents the native hover-only event and recommends moving custom painting to DrawSubItem: https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.listview.drawitem

The new Windows regression failed against the previous painter, then passed after the change. It invokes the real control's drawing callbacks, checks four independently clipped cells, and verifies that twenty hover-only events leave the rendered pixels unchanged. This checks the event-level cause; it does not substitute for a live pointer/scroll/DPI check on the installed application.

## Findings, highest priority first

| Priority | Finding and evidence | Recommended improvement |
|---|---|---|
| High | AI helper instructions promise that nothing is overwritten (`TransferAssistant.Instructions`), while `FileLink.Receive` constructs `FileReceiver` with overwrite enabled. `FileManager.Run` routes accepted AI plans through the ordinary copy path. README also contains conflicting old/new descriptions. | Add an explicit conflict policy: Ask, Skip, Keep both, Replace. Preview existing destination names before execution and apply the chosen policy in both transfer directions. Correct the helper instructions and manual together. |
| High | `MainWindow.RefreshHosts` swallows relay availability errors and initializes each PC as Offline. A relay-only PC becomes red even when its actual availability is unknown. LAN probes run sequentially, so many unreachable PCs delay the whole refresh. | Separate Online, Offline, Checking and Status unavailable; show last successful check and relay health. Use bounded parallel probes, cancellation on window close, and per-device timeouts. Test relay outage separately from a host being offline. |
| High | `IdentityStore.Save` and `Audit` perform synchronous disk writes; periodic refresh is an async timer event with no outer failure handler. Disk-full/access errors can escape into UI event handling. Startup loading rejects corrupt protected settings without a recovery flow. | Add guarded persistence and visible save failures, preserve a last-known-good protected backup, and offer recovery without silently regenerating identity or weakening trust. Rotate logs and test disk-full, denied access and damaged settings. |
| High | Local folder enumeration uses `IgnoreInaccessible=true`; local/remote walkers stop adding entries at `MaxItems` (`TransferStrip`/`TransferBatch`). Selected folders can be incomplete without a detailed skipped-items manifest. | Produce a preflight manifest, report unreadable/excluded/truncated entries, and never describe a partial batch as complete. Fail clearly at hard limits. Add permission-denied and oversized-folder checks. |
| Medium | README and acceptance documents explicitly leave real two-PC capture/input and mixed-DPI acceptance pending. Local suites do not establish usable performance across real networks. | Make a two-PC release checklist mandatory: both directions, Wi-Fi loss/recovery, VPN, sleep/wake, mixed DPI, multiple displays, large transfers alongside control, revocation and disconnect from either end. Record latency, memory and results. |
| Medium | Release documentation describes unsigned builds. The updater checks HTTPS download hosts, size and SHA-256, but does not verify an independent publisher signature before launching setup (`AppUpdates`, `UpdateCenter`). | Sign executable and installer, verify expected publisher before installation, and protect the release workflow. A checksum served by the same release source proves integrity, not independent publisher identity. |
| Medium | `build.ps1` packages a source ZIP from an explicit directory list that omits `relay/`, and runs only the two .NET suites. Relay test success currently depends on a separate command. | Include relay source, lockfile and configuration in source releases, excluding dependencies and local state. Run relay tests in the release pipeline and check that archive contents can reproduce all components. |
| Medium | Refresh/connect paths are not consistently linked to the main window lifetime; `Reach` lets losing connection attempts finish and disposes successful late results. UI shutdown stops the timer but does not cancel an in-flight refresh. | Introduce a shared window lifetime token, cancel obsolete attempts and drain background work on close. Add close-during-connect, remove-during-refresh and simultaneous shutdown tests. |
| Low | The table header allocates a Font on every draw without disposal; the row-height ImageList and timer lifetimes also deserve explicit ownership (`MainWindow.StyleDeviceList`). | Dispose drawing resources deterministically and measure GDI handle/memory growth during repeated refresh, resize and opening/closing windows. |

These are review findings and proposed follow-up work; only the table painting bug is changed in this update.

## Best next features for this app

1. **Connection health and diagnostics.** One clear panel showing relay reachability, chosen route, last successful contact, latency and a plain-language failure reason. Add a redacted support export excluding keys, codes, paths and file contents. This directly addresses misleading status and difficult troubleshooting.
2. **Safe transfer preview and results.** Show direction, destination, totals, conflicts and skipped folders before Run. Finish with a manifest of copied, replaced, skipped and failed items. Offer retry-failed and resumable transfers with size/hash revalidation and session-bound authorization.
3. **Reconnect with visible progress.** Bounded retries with backoff, Cancel, and fresh identity/trust validation. Preserve consent requirements and host revocation; never silently restore control after trust changes. Current manual Reconnect UI is a useful starting point.
4. **Start at sign-in and close to tray.** Opt-in behavior with an obvious running/offline indicator and Quit. This would improve availability within the current signed-in-host model. Lock-screen/reboot access requires a separately designed service and is a larger project.
5. **Searchable session history.** An in-app list with timestamps, direction, view/control mode, attended/unattended access and end reason; filters, export and retention settings. Existing metadata-only audit events provide a foundation.
6. **Remembered quality settings and adaptive quality.** Start with the last successful per-PC profile, then adjust to measured latency/frame acknowledgement time. Surface a simple quality/speed control and preserve sharp text when possible.

Suggested order: transfer conflict safety and truthful status first; persistence/shutdown hardening next; then diagnostics, two-PC release acceptance, signed releases, and convenience features.

## Existing strengths worth preserving

Certificate-pinned mutual TLS, protected identity/settings, explicit pairing and revocation, Windows Hello gating unattended changes, a visible host session indicator and End action, session-scoped file grants, SHA-256 before committing received files, bounded frame/input queues, and a local-only AI endpoint are present in source. Keep these boundaries when adding convenience features.
